2. Why study deep RL?

  1. Beyond supervised examples. Predictions have consequences (recommenders, chatbots, control). RL is the framework for optimizing behavior under those consequences.
  2. Indirect / non-differentiable supervision. “Thumbs up,” sparse task success, coding-assistant quality — not a labeled output \(y\). Any scalar objective can be cast as RL.
  3. Deployed in performant systems. Legged robots, manipulation (laundry, origami), Go (AlphaGo / Move 37), LM post-training & reasoning, traffic control, generative-model alignment, chip design (e.g. Google TPU placement), etc.
  4. Learning from experience ≈ fundamental to intelligence. Improve with practice; discover strategies not in the demo data (not just mimicry).
  5. Open research problems. Reward learning, generalization, scale + transfer, long-horizon tasks, fully autonomous practice / reset-free RL.
Sparse reward practical point (from Q&A): If reward is \(1\) only when the towel is hung and \(0\) otherwise, naive exploration may never succeed. Often you need demos / BC init to jump-start exploration under sparse rewards.

3. Supervised learning vs reinforcement learning

Supervised learningReinforcement learning
Objects Input–output pairs \((x, y)\) States/observations → actions via policy \(\pi\)
Supervision Direct label: “output this \(y\)” Indirect: reward / preference / success from experience
Data Assumed i.i.d.\ from a fixed distribution Not i.i.d.; distribution depends on the policy being learned
Dataset shape Many \((x,y)\) Trajectories (rollouts / episodes), often with rewards
Goal Predict \(y\) given \(x\) Learn behavior \(\pi(a\mid s)\) that maximizes expected return
The two big differences to remember on every exam / interview: (1) no direct answer labels — only experience + reward; (2) data distribution depends on \(\pi\) (closed loop).

4. Representing experience as data

State \(s\) — full relevant configuration of the world for decision-making (e.g. arm pose + towel pose + hook pose; or image + joint angles if that is treated as sufficient).
Observation \(o\) — what the agent actually receives; may be incomplete. Past observations may be needed (chatbot last message alone ≠ full conversation state).
Action \(a\) — the decision / control the agent applies.
Trajectory \(\tau\) — sequence of states (or observations) and actions: \(\tau = (s_1,a_1,s_2,a_2,\ldots,s_T,a_T)\) (or with \(o_t\)). May be augmented with rewards \(r_t\).
Reward function \(r(s,a)\) (often \(r(s)\) only) — how good is this state/action. Examples: towel hung?; user thumbs up/down; distance to goal (negative distance).

State vs observation (core distinction)

  • States: Markov — next state depends only on current state + action.
  • Observations: may be partial; future observations generally depend on history, not just last \(o\) and \(a\).
  • Practical fix for POMDPs: feed a short history (or a recurrent/sequence model) and treat that as an approximate state.

5. Dynamics, Markov property, MDP / POMDP

Interaction as a chain:

\[ s_1 \xrightarrow{a_1} s_2 \xrightarrow{a_2} s_3 \xrightarrow{a_3} \cdots \]
Dynamics / transition model \[ p(s_{t+1}\mid s_t, a_t) \] How the world evolves given current state and action (arm motion, towel motion, other agents, etc.). Usually unknown.
Markov property \[ s_{t+1}\;\perp\; s_{1:t-1} \mid (s_t, a_t) \] Equivalently: \(p(s_{t+1}\mid s_{1:t}, a_{1:t}) = p(s_{t+1}\mid s_t, a_t)\). Lets algorithms factor problems without conditioning on the entire past.

With observations only, \(o_{t+1}\) is generally not independent of past \(o\)’s given only \(o_t,a_t\), because \(o\) may omit velocity, contact history, conversation context, etc.

Markov Decision Process (MDP) — when the agent sees states.
Ingredients (introduced by name at end of lecture): states, actions, reward, initial-state distribution \(p(s_1)\), dynamics \(p(s'\mid s,a)\).
Partially Observable MDP (POMDP) — agent sees observations \(o\) of latent states.

Why \(r(s,a)\) and not only \(r(s)\)?

Often reward depends only on state (progress, success). Action dependence appears when you penalize effort/energy (e.g. large motor torques while walking).

7. Representing behavior: the policy

Policy \(\pi_\theta\) — maps states/observations (or histories) to actions. \(\theta\) = parameters (NN weights). Architecture: MLP, CNN, Transformer, linear model, generative model over actions, …

Acting / rollout loop

  1. Observe \(s_t\) (or history of \(o\)’s).
  2. Sample \(a_t \sim \pi_\theta(\cdot\mid s_t)\) (forward pass).
  3. Execute in environment; receive \(s_{t+1}\) (and \(r_t\)).
  4. Repeat → one rollout / episode = one trajectory generated by \(\pi\).

Memory

  • True state input → no history required (Markov).
  • Observations only → give the policy memory (history / RNN / Transformer). Cost: more compute & memory.
  • Optional two-stage: infer latent state, then act from that state.

Why stochastic policies?

  1. Exploration: try different strategies while learning (tennis practice analogy).
  2. Modeling multimodal human/demo data: people take different valid actions; generative policies help.

8. The RL objective

Goal: maximize reward over the whole trajectory, not one step.

\[ R(\tau)=\sum_{t=1}^{T} r(s_t,a_t) \]

Why is return not deterministic?

Two primary sources of randomness (lecture emphasis):

  1. Stochastic dynamics \(p(s_{t+1}\mid s_t,a_t)\).
  2. Stochastic policy \(\pi(a_t\mid s_t)\).

Also: random initial state \(p(s_1)\). Stochastic rewards / nonstationary goals can usually be pushed into the state without loss of generality; lecture typically keeps \(r\) deterministic.

Trajectory distribution

\[ p_\theta(\tau) = p(s_1)\prod_{t=1}^{T} \pi_\theta(a_t\mid s_t)\, p(s_{t+1}\mid s_t,a_t) \]

\(T\) need not be fixed (variable horizon / conversation length); fixed \(T\) is just easier to write.

Expected return (the thing we maximize)

\[ J(\theta) =\mathbb{E}_{\tau\sim p_\theta}\big[R(\tau)\big] =\mathbb{E}_{\tau\sim p_\theta}\Big[\sum_{t=1}^{T} r(s_t,a_t)\Big] \]
\[ \theta^\star \in \arg\max_\theta\, J(\theta) \]
\(\pi\) does not appear “inside” \(R(\tau)\) as a free symbol — it shapes the distribution \(p_\theta(\tau)\) over which we take the expectation. Much of the course is how to optimize \(J\) despite that.

Discounted return

Equal weight on all times may be undesirable (care more about now than 1000 years out). Discount \(\gamma\in(0,1]\):

\[ R_\gamma(\tau)=\sum_{t=1}^{T}\gamma^{t-1}\, r(s_t,a_t) \quad\text{(indexing conventions vary; idea is \(\gamma^t\) decay)} \]
  • \(\gamma=1\): undiscounted sum.
  • Smaller \(\gamma\): greedier / more myopic.

Discount factors return in later lectures; memorize the role now.

9. How good is a policy? Value & Q

Introduced lightly — used heavily from next week onward.

State value \(V^\pi(s)\) — expected future return if you start in \(s\) and follow \(\pi\) thereafter. \[ V^\pi(s) =\mathbb{E}_{\tau\sim p_\theta}\Big[\sum_{t=0}^{T-1}\gamma^t r(s_t,a_t)\ \Big|\ s_0=s\Big] \] (exact horizon / indexing as in slides; conceptual definition matters today.)
Action value \(Q^\pi(s,a)\) — expected future return if you start in \(s\), take action \(a\) (possibly ≠ \(\pi\)), then follow \(\pi\).

If you cannot score policies, you cannot systematically improve them — values are the scoring tools.

10. Algorithm families (roadmap)

FamilyIdea
Imitation learningMimic a high-reward (or expert) policy from demos
Policy gradientsDifferentiate \(J\) / learn from on-policy practice
Actor–criticEstimate value of current \(\pi\); use it to improve \(\pi\)
Value-basedEstimate value of optimal policy; read off a good policy
Model-basedLearn dynamics \(p(s'\mid s,a)\); plan or improve \(\pi\) with the model

Why so many algorithms? (vs “just SGD” in SL)

  • Cost of collecting data (sim vs humans vs robots).
  • What supervision exists (demos, dense rewards, preferences).
  • Stability & ease of tuning vs sample efficiency.
  • Action space: discrete vs continuous, dimensionality.
  • Whether dynamics are easy to learn.
Different methods make different trade-offs under different assumptions.

12. Lecture Q&A distilled

Q. Real-world reward for block insertion?
Often shaped as negative distance between object and goal; sometimes proprioception or mocap provides positions. Hard in general → reward learning is a real research need.
Q. How much observation history to recover state?
Heavily domain-dependent. Many robotics stacks use current sensors; tactile alone is highly partial; vision helps. Sequence models / short windows are common.
Q. Why isn’t future \(o\) independent of past \(o\)’s?
Observations omit parts of state (e.g. intermittent contact). Older observations can carry information the latest \(o\) lost. Graphically: marginalizing latent states couples the \(o\)’s.
Q. Sparse \(0/1\) success — how does learning start?
Demo initialization / exploration jump-start; otherwise reward may stay zero forever.
Q. Always call everything an observation because sensors are noisy?
You can, but long histories are expensive. Often approximate as a state even if rare sensor failures exist, for algorithmic convenience.
Q. Condition on both \(s\) and \(o\)?
If \(s\) is truly complete, \(o\) adds nothing. History helps for observations, not for true states.
Q. Stochastic rewards / changing goals?
Often re-modeled as part of state or as a new decision process; keep \(r\) deterministic when possible.
